The Enterprise Problem

Why legacy test migration is fundamentally broken

Core Insight: The real enterprise problem is not code conversion — it is test-estate modernization.

Legacy Automation Sprawl

Enterprises accumulate automation across UFT, Selenium, Cypress, Playwright, Robot Framework, Tosca, and custom frameworks — creating fragmented, costly estates.

Traditional Migration Fails

Point-to-point conversion (Source → Target) ignores duplicate tests, framework mismatches, obsolete flows, and doesn't prove behavioral equivalence.

Six Limitations of Traditional Migration

1. Framework constructs rarely map one-to-one

2. Legacy suites contain obsolete, duplicate, and low-value tests

3. Syntax conversion ≠ equivalent business validation

4. Generated tests may violate target engineering standards

5. Enterprise becomes locked into yet another framework

6. No mechanism to control future test-estate degradation

AI Understanding

Converts technical constructs to business semantics:

// Legacy UFT: Browser(...) → Page(...) → WebEdit.Set → WebButton.Click // Recovered Intent: Business: Claim Approval Pre: Authorized examiner Action: Search and open claim Action: Approve claim Assert: Status = Approved

Test Intent Model (TIM)

The most strategically important platform asset

Principle: TIM is not another programming language. It models what the test means, retaining enough technical metadata for regeneration and validation.

Illustrative Schema

{ "test_id": "TIM-001", "name": "Approve eligible claim", "business_capability": "Claim Approval", "preconditions": [...], "steps": [ { "intent": "search_claim", "channel": "ui", "input_refs": [...], "evidence_refs": [...] } ], "assertions": [ { "intent": "verify_claim_status", "expected": "Approved" } ], "confidence": {...}, "source": { "framework": "UFT" } }

Risks & Controls

Known risks with established mitigations

⚠

Hallucinated Test Intent

Control: Deterministic source evidence, structured schemas, confidence scoring, human review

⚠

Generated Code Changes Behavior

Control: Execution-based behavioral validation, not just pass/fail comparison

⚠

Sensitive Data Reaching External Models

Control: Data classification, redaction/tokenization, approved model endpoints, enterprise security policy

△

Over-Engineering

Control: Phased architecture, explicit MVP boundaries, no premature complexity

△

Vendor Lock-in

Control: Model and framework abstractions, TIM independent of LLM provider and target

△

Low-Value Tests Migrated at Scale

Control: Rationalization engine before mass migration

△

Autonomous AI Causing Regression

Control: Approval gates and controlled repository workflows
